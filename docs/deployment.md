# Deployment guide

Three deployment options, in order of maturity.

## 1. Docker Compose (dev / small)

Zero-configuration bootstrap. Ship the compose file + .env and
`docker compose up -d`. `yggdrasil init` automates the whole thing
(see [getting-started.md](./getting-started.md)).

File: [`docker-compose.standalone.yml`](../docker-compose.standalone.yml).

Default passwords come from `.env` (random when generated by
`yggdrasil init`). Persistence lives in named Docker volumes —
`docker compose down` is safe; `docker compose down -v` wipes data.

Good for:
- Trying Yggdrasil on a laptop.
- Demo and workshop environments.
- Single-host self-hosted deployments for ≤ 50 adopters.

Not good for:
- Multi-node HA.
- Cluster-backed persistence.
- Centrally managed secrets.

## 2. Kubernetes via Helm (production)

The chart at [`chart/`](../chart) packages yggdrasil-core plus a
bundled Postgres into one release. Default is HTTP-only —
`rabbitmq.enabled` is `false` in `values.yaml`. Enable the bundled
RabbitMQ subchart (or any other `rpc.Transport` backend you register)
via values only if you need it; see
[features/transports.md](./features/transports.md).

### Install

```sh
helm repo add bitnami https://charts.bitnami.com/bitnami
cd yggdrasil-core
helm dependency update chart
helm install yggdrasil chart \
  --namespace yggdrasil \
  --create-namespace \
  --set ingress.enabled=true \
  --set "ingress.hosts[0].host=yggdrasil.example.com" \
  --set ingress.className=nginx \
  --set session.cookieDomain=example.com
```

Retrieve the auto-generated admin password:

```sh
kubectl get secret --namespace yggdrasil yggdrasil-yggdrasil-core-secrets \
  -o jsonpath='{.data.admin-password}' | base64 -d
```

Then `yggdrasil login` with that password.

### Production sizing

| Variable | Recommended |
|---|---|
| `replicaCount` | 2 (HA) or 3 (extra) |
| `autoscaling.enabled` | `true`, min 2, max 10 |
| `resources.requests.cpu` | 200m |
| `resources.requests.memory` | 256Mi |
| `postgresql.primary.persistence.size` | 32Gi (grows with event_log) |
| `rabbitmq.persistence.size` | 8Gi (only if AMQP backend enabled) |

### External managed Postgres

If you run Postgres as a managed service (RDS, Cloud SQL, Neon):

```yaml
postgresql:
  enabled: false
external:
  postgres:
    host: my-db.internal
    port: 5432
    database: yggdrasil
    username: yggdrasil
    passwordSecret:
      name: yggdrasil-db
      key: password
```

Create the secret before installing:

```sh
kubectl create secret generic yggdrasil-db \
  --namespace yggdrasil \
  --from-literal=password=$DB_PASSWORD
```

### Optional: AMQP transport backend

The AMQP `rpc.Transport` backend is **opt-in and off by default**
(`rabbitmq.enabled: false` in `values.yaml`). Skip this section
entirely if your integrations all speak `http_json`. If any
`integration_type` in your catalog declares `transport: rabbitmq`,
turn a backend on:

- **Bundled**: set `rabbitmq.enabled: true` to pull the
  `bitnami/rabbitmq` subchart.
- **External managed** (recommended for prod):

```yaml
rabbitmq:
  enabled: false
external:
  rabbitmq:
    urlSecret:
      name: yggdrasil-amqp
      key: url
```

The secret value is the full AMQP URL (`amqp://user:pass@host:5672/`).
When both `rabbitmq.enabled` is false and `external.rabbitmq.urlSecret.name`
is empty, the chart doesn't set `BROKER_URL` at all — the core boots
HTTP-only. Other `rpc.Transport` plug-ins follow the same "register an
addon + set its env var" pattern; consult each plug-in's docs.

### TLS / session cookie

Set `session.cookieSecure: true` (default) and front the ingress
with TLS. If your ingress controller terminates TLS on a wildcard
like `*.example.com`, set `session.cookieDomain: example.com` so
the console and the API share sessions.

## 3. Custom / bare-metal

Yggdrasil-core is a single Go binary. Minimum environment:

```sh
export DB_HOST=localhost DB_PORT=5432 DB_NAME=yggdrasil \
       DB_USER=yggdrasil DB_PASSWORD=xxx \
       PORT=9080
./goose up               # once, after each upgrade
./yggdrasil-core         # starts serving
```

The HTTP API is always served on `PORT`. Additional `rpc.Transport`
backends are opt-in — set their env vars only if you need them (e.g.
`BROKER_URL=amqp://user:pass@localhost:5672/` enables the AMQP
backend; other transports expose their own config variable).

For first-run bootstrap add:

```sh
export YGGDRASIL_BOOTSTRAP_ADMIN_USERNAME=admin \
       YGGDRASIL_BOOTSTRAP_ADMIN_PASSWORD=your-strong-password \
       YGGDRASIL_BOOTSTRAP_MANIFESTS_PATH=/app/docs/bootstrap/manifests
```

Manage the process with systemd, supervisord, or whatever fits your
environment.

## Upgrades

See [upgrade.md](./upgrade.md). Short version: the schema is
goose-versioned and additive across patch versions; run `goose up`
and restart. Minor/major upgrades may deprecate manifest fields —
the release notes list them individually.

## Backup and restore

Yggdrasil state lives entirely in Postgres. Use your standard
Postgres backup (`pg_dump`, WAL archiving, managed snapshot). Any
`rpc.Transport` backend state is transient (e.g. AMQP queues are
re-declared on boot by the adapters themselves).

Restore = restore Postgres + bring any transport backends back up +
start the pods. Integration adapters recover autonomously.

## Observability

- `/healthz` — process liveness.
- `/readyz` — process + Postgres reachable.
- Structured logs on stdout (zap JSON).
- `event_log` table is your audit trail; tail it or pipe to your
  data lake.
- For metrics, wire a Prometheus endpoint via a surface (the
  first-party console exposes `/metrics`).
