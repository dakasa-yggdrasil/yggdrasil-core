# Original Guest admission and protected retirement

This source lot is experimental, with `FULL_CORE_NATIVE_PENDING`. Its isolated
source, PostgreSQL, authentication and build gates are distinct from the genuine
joint Guest/Core native lifecycle. The production registry remains empty/HOLD.
Neither publication of this source nor a qualified echo fixture activates a
provider or qualifies the full production workload.

## Authority and evidence

The workflow captures one explicit original step context before create. The
store reserves the preregistration, profile, private nonce commitment and mutation
grant before the provider driver redeems the grant and starts its one original.
The accepted settlement is joined to an independent native read before Core
records the signed create witness. Static bootstrap configuration contains no
guessed preregistration, native tuple or later replacement deadline. The original
Guest independently reads its native resource identity before the scoped lookup
and again before bootstrap or writer start.

The original callback names its create witness, complete enclosing bootstrap
journal/observation, actual writer placements and immutable source profile.
Only its one authenticated POST can create enrollment and the exact original
receipt. A response lost after commitment permits the scoped receipt GET, never
a second provisioning attempt. Provisioner and actor principals are separate;
enrollment, intent, provisioning and observation signing purposes remain distinct.

Retirement preserves the shared sixteen DTOs. The transport uses the literal
`/v1/retirement` route for its sole signed POST and same-original GET. Two
independent `before_start` challenges and fresh native snapshots precede start.
The following current `before_poweroff` reads join the original attempt, actor,
runtime and immutable record chain. The reply state remains `authorized` only
after the current checks pass. Each read permission is persisted before its
original GET and cannot be reused for a replacement read.

Four immutable records, two snapshots, four authority replies, five authority
transport returns and the original complete POST caller return are necessary for
successful retirement. Current policy, workflow, source, lease, fencing and floor
are rechecked at issue, after native I/O and at first destroy redemption. Partial
Do/Read/Close failures retain their actual hash/count/time/flag facts but cannot
be decoded as complete quiescence. Missing or unknown enrollment remains HOLD.

Canonical original JSON is kept in BYTEA beside queryable JSONB. Raw JSON and
time identity are never rounded or reconstructed from PostgreSQL's timestamp
representation. `resource_created_at` is the literal tuple key. Original body
bytes use bounded canonical base64 for exactly builtin `[]byte`; aliases,
arrays, omitted/null bodies and noncanonical base64 are not admitted as retained
bytes. Empty retained bytes are explicit and distinct from an absent body.

## Fixed native qualification realm

The Linux `nativequalification` build has a compiled fixed registry for
`qualification-original-echo-writer-v1`. Each case has exactly two real QEMU
originals: slot1 is a live useful baseline and slot2 is the burst/retirement
candidate. A bounded signed useful probe drives the same admitted writer's
original stdin/stdout and independently reads its process, pipes and census.
Physical VM counts cannot substitute for useful capacity.

QEMU resource identity is its independently read UUID and creator PID/PPID/start
ticks. The tuple's creation instant is the actual successful original `Popen`
**return** instant, serialized once as UTC RFC3339Nano. The original call-start
and call-return facts are both retained. This is a qualification-specific
creation-accepted projection, not a provider timestamp or kernel birth claim.

Before the retirement intent, Core pins the same original PIDFD. Poweroff joins
the original Guest operation, frontend `Wait(0)`, stderr EOF/Close, the pinned
PIDFD's actual readiness and Close return. A full `/proc/PID/stat` digest is a
retained read fact, not a stable process identity. The raw off record deliberately
names the original creator's immutable process projection.

Destroy redeems the original permission before unlinking only its original disk.
The remembered precreate disk device/inode is independently joined to a QEMU
opened FD while the process is live. After off, the driver verifies that exact
anchored object, unlinks once, fsyncs/closes its directory, and separately reads
ENOENT through a new anchored directory descriptor. The typed
`core_original_native_qemu_disk_absence_readback_v1` names only that authorized
QEMU disk. It has no billing exposure, invoice, Hetzner label or generic paid
resource absence fields. Production builds refuse this native realm/schema.

The source-only preparation step compiles clean source, pins the image and
prepares immutable files without Core authority, grants or VMs. The next owning
step captures the first and sole UTC/monotonic origin: exact 600s context, approved
420s provisioning budget, with the original native 13m workflow and 150s cleanup
limits unchanged. The Core source request must have nonzero `StartedAt` and
`Deadline == StartedAt + 600s`; there is no tolerance, renewal or profile adaptation.
Protected retirement is the exact minimum of its first context deadline, the
current lease and its original issue instant plus30s. Useful probes are at most5s.
Neither bound extends the captured source context. Native-QEMU tuple creation
and Witness.OriginalCreateReturnedAt use the actual successful Popen return;
the later independent QMP Read/Close remains the settlement/proof observation.

The supplier command is independently compiled from clean actual Core source:

```text
native-guest-lifecycle-fixture --original-native-qemu-fixture \
  --request <private-dir>/original-source-request.json --private-dir <private-dir>
```

It serves the actual production authentication middleware and public workflow
handlers against ephemeral PostgreSQL/RabbitMQ, with source-scoped TLS/principal
inventory. It neither injects context principals nor substitutes successful
phase booleans. Original async workflow owners are tracked and joined under the
same first600 context. Production's nil observer retains Background/30min.
Refusal after the run row was persisted leaves an honest pending row and launches
no worker. Failure cancels that same original context before resource cleanup.
The baseline keeper, HTTP Serve, every original handler and workflow must
actually return before native pins, broker or DB close. Shutdown may refuse
within5s and cause Close/cancel; a timer never substitutes an owner return. The
completed stage is published only after those joins and actual resource closes.

Each private HTTP return records an explicit original body scope:
`no_original_body_read`, `complete_original_body_read`, or
`incomplete_original_body_read`. `received_body_bytes` and `response_sha256`
describe the actual bounded ReadAll buffer, up to65537 bytes, before truncation.
The separate `retained_prefix_bytes` and `retained_prefix_sha256` describe only
the driver's in-memory prefix, up to65536 bytes. Under no-read the original
response digest is unavailable/empty; the empty local prefix digest proves no
Read or EOF. Close and context returns remain independent, including refusal
after complete EOF. Partial/cap+1 reads never authorize or persist a complete
body. `body_persisted=false` retains an explicit empty private SQL body while
preserving those actual hash/count/scope facts. Public projections contain these
facts and untouched SQL envelope hashes, without the private body or nonce.

## Private receipts and public artifact projections

Readonly verification uses the same database after the original supplier, with
`REQUIRE_CAPACITY_GUEST_NATIVE_CORPUS=true`, its original private corpus path and
the literal `GUEST_ORIGINAL_NATIVE_CASE`. It may use a separate bounded readonly
context after the original attempt ends; this grants no effects, renewed lease
or fresh native source fact. Invoke `scripts/ci/capacity_guest_original_corpus.sh`
with `native` for the two positives and `native-hold` for the five refusals.

The script always retains test.jsonl, go-test.stderr, tee.stderr, census.json,
census.stdout and census.stderr, including original process/tee return codes,
missing cases, skips and compile/failure events. Set task-scoped `RUNNER_TEMP` to
the public artifact's `core-readonly-corpus-ci` directory before invocation. A
missing original receipt produces a failing census instead of a skip.

Only the secret-free original corpus bytes can be exported raw. Sensitive SQL
returns have the typed allowlist wrapper
`core_original_guest_nonsecret_return_projection_v1`, with projection class
`typed_allowlisted_facts_not_original_raw_bytes`. Its `original_raw_sha256`
hashes untouched private SQL BYTEA; the projection file SHA is separate. Positive
exports require caller, four journals, two challenges/two snapshots, four
authorities and five transports. Failed ACK exports contain only their actual
partial returns. Public caller facts are also retained on failure. No private
nonce, token/key, certificate, config, ISO, raw signed request, raw body or raw
error is copied into a public artifact.
