# Native placement and member retirement

This optional Source composition is disabled without the protected Members
installation file, exact policy binding, real read counterparts and existing
execution gates. It is not a runtime installation or a claim that a member can
currently be admitted, allocated, drained or replaced. ADR-0151 defines the
lasting decision.

Core uses the standard scheduler's closed Bind extender and the existing
workload identity/lineage contract. The stock TLS principal does not receive SDK
writer credentials. Its official JSON keys are `PodName`, `PodNamespace`,
`PodUID`, `Node`; the response key is `Error`. Aliases are rejected. New Native
workload Pod/Deployment names use `nw-`, scheduler/taint/priority requirements
come from the protected counterpart, and preemption is Never via the fixed
PriorityClass. Existing normal workloads and probe names are not renamed.

The three Kubernetes resource contracts expose seven fixed capabilities:

- `ensure_native_worker_pool_member`: cordon only.
- `destroy_native_worker_pool_member`: one Eviction, Node deletion or registry
  retirement per original permit. No partial member destroyed result.
- `observe_native_worker_pool_member`: independent complete reads.
- `ensure_native_worker_pod_placement`: one native Binding.
- `destroy_native_worker_pod_placement`: one PDB-aware native Eviction.
- `observe_native_worker_pod_placement`: current subject and complete roster.
- `observe_native_worker_allocator_fence`: pre-create read with no fictional
  Node, birth or physical resource.

Every SDK input has only `binding_name` and `permit_id`. Separate mTLS clients,
Source and whole-file scopes own writer, member reader and allocator-fence reader
roles. The dedicated Core listener separates read, writer redemption/original
receiving, reader original custody and controller reconcile. Configz is a fixed
GET over the protected Node identity; its raw body, digest and diagnostics stay
in encrypted private custody. ReadID is issued before the GET. A custody204
is not a configuration proof. Guest configured args and actual process argv are
separate; only authenticated effective configz proves static sources disabled.

Placement parents are current admitted/released membership, useful Node facts,
actual PodUID/contract and the authenticated scheduler. The completed grow lease
is not reused. Effective validity is the minimum of thirty seconds and all
original facts, including each canary, heartbeat, guest, configuration and
physical read. New outer reads never renew old canaries or an exposed permit.
A realm+PodUID SQL barrier spans Nodes, Attempts, pools and epochs. Pending Pod
readback alone never proves an old Bind did not happen.

For the never-admitted opt-in, existing `capacity.recover` accepts only the
active logical policy selector under its exact authorized recovery workflow.
It selects one active plan or eligible Attempt deterministically and advances
at most one original external effect per invocation. Pending is not destroyed
and does not authorize an automatic retry. The original immutable admission
history determines the mode; callers do not choose it.

Retirement fences new probe/admission/release/Bind rights under the existing
Attempt arbiter. Every bound Pod remains in the roster, including terminal,
deleting and DaemonSet Pods; the old nonterminal count is checked separately.
Unmatched/protected/storage-unknown Pods hold. Unowned probes use their original
cleanup port first. Complete zero-Pod evidence is checked again at Abort.Redeem,
not merely by the planner.

Provider and network dispatch barriers commit before their exact existing
writers. Unknown, failed Close, incomplete custody and exposed sends remain
blocked; no timeout or GET remints the original right. Complete bound provider
originals do not prove absence or billing closure. Independent provider and
ancillary absence precede Node deletion, then exact registry retirement. After
physical absence these operations use sealed guest facts and fresh absence,
not a GET to a dead guest. Only the final transaction can mark Attempt absent,
release its IPAM reservation, settle the plan and emit the canonical member
destroyed event using the existing exact Abort settled predicate.

Shutdown seals new rights without waiting for borrowers. After local runtime
join, a separate five-second, database-only guard checks complete Source-bound
original custody for exposed member, configz, provider and network calls. A
local canceled HTTP call is not remote SDK EOF. Missing, partial or uncertain
originals, database errors or bounded-history overflow retain a sticky dependency
barrier before callback listeners, keys, clients and borrowed database/broker
close. Late original receiving stays available; history is never expired or
removed to make shutdown pass. This guard is bounded to 100000 rows per original
family and is not a throughput or scale qualification. Inventory-only cleanup
ReadIDs remain durable and do not invent an expected configz body.

Admitted retirement, NoNode member cleanup and profile handoff are not installed
by this slice. In particular the installer verifier/read port is still missing;
a literal Authority file, Source marker or copied403 cannot qualify current
enforcement/coverage. Its incomplete result holds before paid creation and
placement/admission. No fallback to a legacy cloud destroy, generic Node CRUD,
readonly mount or reused admission server exists.

CI is the only test executor. The separate Members workflow accounts for every
authored unit, real TLS ownership and PostgreSQL16/17 root from exact checkout
Source, rejects missing/repeated/skipped roots and retains original artifacts.
SQL tests use real disposable databases and explicitly synthetic member facts;
TLS ownership tests use actual listeners/owner chains with declared dependency
spies. Neither constitutes live placement, cloud or installer qualification.
