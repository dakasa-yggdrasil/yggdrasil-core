# Fixed native HPA execution

`capacity.execute_bound` accepts only the logical policy namespace/name through
its exact active authorized workflow. Sources, adapter revisions, capabilities,
requests, Pod identities, generation and permissions are constructed privately.
No workflow input supplies pressure evidence, a receipt, provider URL, a drain
boolean or a lease. Generic capacity mutations remain refused for bound policies.

The optional `hpa_execution_binding` keeps execution disabled by default. It binds
the exact adapter machine principal, native Pod binding, container, immutable image,
complete local lane roster and projection path. Both policy and process execution
gates are required. There are no VM mutation bindings for reserved Pod envelopes.

PostgreSQL serializes the logical dimension. One-use opaque commands are bound to
an exact active policy/workflow/adapter revision, current private invocation lease,
full canonical request hash and native phase. The adapter authenticates separately
through the existing capacity principal surface before redeeming once. Native UID
ownership cannot cross logical policy realms. No network occurs under row locks.

HPA tracking generation is monotonic in the native HPA; Core intent generation is
separate and binds Pod challenges. A first Core intent does not overwrite a higher
native HPA generation. Only min/max reservation bounds and tracking annotations
change. Current replicas, useful stock, warm readiness and VM floors are untouched.
Native HPA metadata generation can be zero because the Kubernetes HPA REST strategy
does not increment it on create/update. Exact UID/resourceVersion and the positive
owner envelope generation remain mandatory. This is not a zero-as-wildcard rule.

A reduction records a complete native baseline UID roster and its selected Pod
checkpoints in one transaction. Protection precedes the HPA write. Each challenge
binds exact Pod UID/generation, current container ID/start/restart count, workload
UID, immutable image, Core generation, nonce and all declared local lanes. Annotation
CAS is not projected-file acknowledgement. Missing or late producer data remains
unknown and the native finalizer stays retained.

Each transport outcome is reconciled with an independent fixed native read. Lost
responses never grant another send. A restarted invocation waits for lease expiry
and then resumes only the same durable generation; unresolved commands block all
new commands. Historical commands retain their original executor and evidence.
An issued token can be revoked under the same dimension and row locks as
redemption only while it has no attempt or redeeming actor. Revocation invalidates
the old token and retains its request, identity and hash. A fixed phase permits at
most four such command sequences. Each new sequence uses fresh native reads with
the same lifetime and challenge; an HPA sequence also refreshes every pressure
source. A redeemed or uncertain command remains read-only until its native outcome
is confirmed. A resourceVersion refusal never relaxes the native CAS.

Current native Terminated exit-zero state and the complete bounded canonical local
receipt are stored durably before finalizer acknowledgement is issued. Previous
container termination, timeout, Close and missing metrics cannot confirm a lifetime.
Completion requires the one real HPA confirmation and all three real confirmations
per selected lifetime, every selected checkpoint released and
no missing baseline Pod outside the confirmed roster. A controller removal without
its exact retained witness leaves the operation pending. Direct deletion may create
a Deployment replacement; this protocol does not infer released fleet capacity.

Durable business uncertainty, external provider mutations, useful capacity and
fleet/platform quiescence remain separate barriers. This source introduces no live
activation, scheduler, provider purchase, deployment or VM floor change.
