# ADR-0047: Observe the original live lease before a private Notify canary

- **Status:** Proposed
- **Date:** 2026-10-11
- **Deciders:** DaKasa platform owners
- **Scope:** yggdrasil-core / original finite private useful canary
- **Supersedes:** —
- **Superseded by:** —

## Context

Native HPA admission and reservation bounds do not prove a useful business
return. A scheduled machine must not impersonate an existing human session or
borrow a Directory credential. A late writer marker also cannot establish that
its original writer or outer owner actually returned. Uncertain original work
must remain an obligation across owner expiry, new generations and config changes.

## Decision

Require the existing original dispatcher, current authorization and SAME live
intent lease to own an opt-in finite Notify prerequisite before reservation
completion. Freeze the original typed scope and complete native participant
roster, commit a durable possible-start marker and observe its actual original
acknowledgment before process-local registration, all participant installs and
one publisher arm. Keep the bearer only in original memory/private headers.

Use operator-fixed provider-neutral product HTTPS controls and the current
read-only native supplier. Preserve every original Do/Read/Close and context
cause under its absolute owner deadline. Join original native SQL/business XID
and recipient rows with current native B identity and received original writer
and owner returns. After one seal and the final source join, require its actual
marker Commit acknowledgment and current guards before the existing Complete.
Retain uncertainty permanently and forbid replay or reminting after unknown
original outcomes. Preserve legacy behavior only when the binding is absent
and no unresolved original marker remains.

## Consequences

The first prerequisite measures one original call and at most eight read rounds,
without changing the original registry, request, lease or owning workflow limits.
It supplies no continuous/warm/all22/drain/physical-capacity certificate. The
private owning Notify joint CI must exercise original compiled Core `RunOne`
against real managed workers; public protocol fixtures cannot substitute that
evidence. Reviewed immutable CI source pins can precede that joint qualification;
production activation still needs qualified components and approved bindings.

Direct mounted TLS identity and original Core process affinity remain operator
prerequisites. No new account, session, grant, provider action, business ledger,
SDK message format, migration or public registration route is created.
